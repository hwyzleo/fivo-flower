# FIVO 的花花 — SPEC 开发计划

- 文档版本：v1.0

> **变更提示（2026-11-17，补丁 12）**：AI 小花灵（植物识别、养护问答）、AI 订单解析增强、AI 服务配置与 Keychain 凭据管理已从 App 中移除；右上角「提醒中心」此前已在补丁 10 移除。本文档中相关章节仅作为历史设计记录保留，不再代表当前实现。当前版本不发起任何网络请求，订单导入仅使用设备端 OCR 与本地解析，未授权的通知由「养护日历」Tab 兜底。

- 对应文档：[SPEC 需求](./SPEC_REQUIREMENTS.md) · [SPEC 设计](./SPEC_DESIGN.md)
- 目标：交付可安装、可备份、核心流程完整的首版 iPhone MVP

## 1. 实施策略

按“本地数据骨架 → 植物核心 → 持续记录 → AI 与资产 → 数据安全 → 发布验证”推进。每个里程碑必须可运行、可测试，不在最后阶段集中补数据规则和异常处理。

### 1.1 工作量估算

以 1 名熟悉 SwiftUI/SwiftData 的 iOS 开发者、UI 规范已确认为前提，预计 **40–50 个工作日**，不含 App Store 审核等待和第三方 AI 服务商务准备。

估算包含单元测试、关键 UI 测试和 TestFlight 修复，不包含真实硬件控制、iCloud 同步及后端建设。

### 1.2 发布门槛定义

- P0：崩溃、数据丢失、账目错误、状态计时错误，必须阻断发布。
- P1：核心流程无法完成、备份无法恢复、权限拒绝无替代路径，必须阻断发布。
- P2：局部视觉、动画、非核心文案问题，可记录后迭代。

## 2. 里程碑

### M0 — 工程与质量基础（2 天）

**任务**

- 创建 iOS 17 SwiftUI 工程、App 入口和模块目录。
- 配置 SwiftData 版本化容器、内存测试容器和文件目录。
- 建立 Repository/Service 协议、依赖装配和基础错误类型。
- 配置单元测试、UI 测试、Swift 并发和基础 CI 命令。
- 加入应用显示名 FIVO 的花花及权限占位文案。

**交付**：可运行空 App、五栏导航骨架、测试 Target。

**验收**：干净环境可构建；测试容器与真实容器隔离；无硬编码用户数据。

### M1 — 设计系统与本地数据骨架（4 天）

**任务**

- 实现色彩、字体、间距、圆角和 Tactile Soft UI 阴影 Token。
- 实现 SoftCard、输入框、搜索框、主按钮、筛选 Chip、状态标签和空/错状态。
- 建立核心 SwiftData 实体、DTO 边界和基础 Repository。
- 实现图片原图/缩略图存储、相对路径和清理策略。
- 建立日期、金额和日历测试工具。

**交付**：组件预览页、可持久化基础数据、图片服务。

**验收**：Dynamic Type 和减少动态效果下组件可用；长列表缩略图和阴影无明显卡顿。

### M2 — 花房与植物档案（5 天）

**任务**

- 完成手动新增、编辑、校验、详情和复制。
- 实现死亡/赠送、恢复、删除及关联数据处理。
- 实现分类计算、陪伴天数、首页数量、搜索、筛选和排序。
- 实现照片选择、照片墙、全屏查看、封面裁剪。
- 编写分类、周年、日期和删除规则测试。

**交付**：完整植物 CRUD 与花房首页。

**验收**：需求 FR-HOME、FR-PLANT、FR-PHOTO 的相关场景通过；购买当天、满 1 年、满 2 年及闰日边界正确。

### M3 — 生长状态、日志与植物统计（5 天）

**任务**

- 实现预设/自定义生长状态和单进行中 Session 约束。
- 完成状态切换、历史、当前天数和自动日志。
- 实现手动日志、单株时间线、全局档案日志和筛选。
- 实现出花梗间隔、频率、开花时长和单株/全局统计。
- 添加固定日期、跨年和进行中记录测试。

**交付**：植物完整生长时间线和统计。

**验收**：连续状态切换无重叠进行中记录；统计可用手工样本复算；自动日志不重复。

### M4 — 养护动作与提醒（4 天）

**任务**

- 实现内置/自定义养护类型及历史名称快照。
- 实现单株和批量养护、照片、用量、日志联动。
- 实现每 N 天、每 N 周、每 N 月、每 N 年周期及本地通知，清理旧仅一次和按星期数据。
- 实现植物详情添加/修改周期、日历完成、当前待办自动调整及低库存提醒通用结构。
- 实现手动/批量养护自动完成对应待办，处理权限拒绝、设备重启和应用前台的通知对账。

**交付**：完整养护记录与周期待办闭环。

**验收**：批量记录独立且共享批次；仅在完成后生成下一待办；修改周期和手动养护联动正确；通知不重复；无通知权限时应用内待办仍正确。

### M5 — 订单导入与 AI 小花灵（7–9 天）

**任务**

- 接入 PhotosPicker 和 Vision OCR，建立临时附件流程。
- 实现本地订单基础解析、AI 增强解析、字段校验和确认页。
- 实现重复提示、多截图、失败回退及可选自动采购账目。
- 建立 AIProvider 协议、Mock、通用 OpenAI-compatible HTTP Adapter 和 Keychain 配置。
- 实现植物识别、候选结果、养护问答、单株上下文选择与隐私提示。
- 添加结构化 JSON 契约、超时、取消、限流和错误注入测试。

**交付**：订单导入全流程及可替换 AI 功能。

**验收**：未配置 AI 时 OCR 和手动流程可用；Mock 全路径 UI 测试通过；真实 Provider smoke test 通过后方可标记 AI 生产可用。

**外部依赖**：M5 联调前需确定一个兼容端点、模型及测试凭据。共享生产密钥不得嵌入 App；若使用共享服务，另立后端代理任务。

### M6 — 工具资材、账本与金额统计（6 天）

**任务**

- 实现工具分类、档案、消耗品库存、库存历史和设备手动状态。
- 实现账目 CRUD、支出/收入/退款、来源关联和搜索筛选。
- 打通植物/工具创建时可选采购账目及价格同步确认。
- 实现累计投入、分类汇总、月度趋势和年度筛选。
- 编写金额精度、退款、删除档案和防重复测试。

**交付**：花园账本、工具库和统计。

**验收**：所有汇总可用固定样本复算；删除档案默认保留账目；设备开关无真实控制误导。

### M7 — 设置、备份与导出（3–4 天）

**任务**

- 完成设置、自定义类型管理和 AI 服务配置入口。
- 实现版本化 `.fivoflower` 备份、媒体打包和校验。
- 实现安全备份、整体替换恢复和失败回滚。
- 实现植物/账本 CSV 导出及系统分享。
- 实现清空数据、隐私说明和权限设置跳转。

**交付**：本地数据安全闭环。

**验收**：备份—清空—恢复 round-trip 一致；损坏包不改变现有数据；CSV 中文和特殊字符正确；API Key 不进入备份。

### M8 — 集成、性能与 TestFlight（5–6 天）

**任务**

- 执行第 7 节全部端到端场景及权限/离线矩阵。
- 使用大样本检查首页、日志、照片墙和账本性能。
- 完成 VoiceOver、Dynamic Type、对比度和减少动态效果检查。
- 补齐空状态、错误文案、数据迁移回滚和崩溃修复。
- 准备图标、启动页、版本号、隐私清单和 TestFlight 构建。

**交付**：候选发布版本、测试报告和已知问题清单。

**验收**：无 P0/P1；核心自动化测试通过；AI 真实服务、备份恢复及全新安装路径均完成人工验收。

## 3. 建议开发顺序与检查点

| 检查点 | 完成里程碑 | 可演示能力 |
|---|---|---|
| CP1 植物核心 | M0–M2 | 手动新增植物、封面、分类、筛选、归档 |
| CP2 持续记录 | M3–M4 | 状态计时、日志、统计、养护和提醒 |
| CP3 智能导入 | M5 | OCR/AI 导入、识别和问答 |
| CP4 完整 MVP | M6–M7 | 工具、账本、备份和导出 |
| CP5 测试候选 | M8 | TestFlight 候选版本 |

每个检查点先验收业务规则，再继续扩展 UI，避免在错误数据模型上堆叠功能。

## 4. 测试计划

### 4.1 单元测试

- 植物分类：无购买日期、购买当天、周年前后、闰年、死亡/赠送和恢复。
- 天数：开始当天、结束当天、跨月/年、未来日期拒绝。
- 状态机：连续切换、同时间结束/开始、单进行中约束、归档关闭状态。
- 统计：相邻出花梗间隔、无间隔样本、进行中开花排除、年度过滤。
- 账本：Decimal 精度、退款方向、收入不冲减投入、来源防重复。
- 库存：增加、减少、校准、负库存拒绝、低库存边界。
- 导入：字段解析、无效 AI JSON 回退、重复订单提示。
- 备份：DTO 编解码、版本拒绝、媒体引用和 CSV 转义。

### 4.2 数据集成测试

- SwiftData 增删改查、事务回滚和唯一约束。
- 创建植物 + 初始状态 + 日志 + 可选账目的一致性。
- 删除源记录与自动日志/照片/提醒的关联行为。
- Schema 从旧版本升级及数据保留。
- 文件存储失败、媒体缺失和恢复失败回滚。

### 4.3 UI 测试

- 首次启动空花房到创建首株植物。
- 截图导入确认及识别失败手动完成。
- 状态切换、批量浇水、周期完成与手动养护联动。
- 工具库存、手动记账和退款。
- AI Mock 成功/失败/取消。
- 备份、清空、恢复和 CSV 分享。

### 4.4 人工设备矩阵

至少覆盖：

- 一台较小屏 iPhone 和一台大屏 iPhone。
- 当前最低 iOS 17 系统及一个较新 iOS 版本。
- 中文、Dynamic Type 放大、VoiceOver 核心路径。
- 无网络、弱网、AI 超时、拒绝相机/相册/通知。
- 大量照片、后台恢复、设备重启和存储空间不足模拟。

## 5. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 各平台订单版式差异大 | 导入字段不稳定 | OCR 本地解析 + AI 增强 + 必确认；保留手动路径，不追求零编辑 |
| AI Provider 尚未确定 | M5 真实联调受阻 | 先协议、Mock 和通用 Adapter；将真实端点作为 M5 外部依赖 |
| 客户端共享 API Key 泄露 | 安全和费用风险 | TestFlight 用户凭据入 Keychain；共享凭据必须后端代理 |
| 大量拟物阴影影响列表性能 | 滚动掉帧 | 简化长列表阴影、缩略图、性能实测，不为视觉牺牲交互 |
| 照片增长占用空间 | 存储和备份缓慢 | 缩略图、相对路径、备份媒体校验；后续增加空间管理 |
| SwiftData 迁移或关联删除 | 数据丢失 | 版本化 Schema、迁移测试、事务边界和恢复前安全备份 |
| 日期/周年/时区口径不一致 | 分类和统计错误 | 统一纯领域计算器，注入 Calendar，覆盖边界测试 |
| 本地通知与应用状态不一致 | 重复或漏提醒 | Reminder 为事实源，前台对账 pending notification |
| 首版功能面较大 | 里程碑延期 | 按检查点验收；视觉动效和非核心统计最后裁剪，不削数据安全 |

## 6. 完成定义（Definition of Done）

每项功能只有同时满足以下条件才算完成：

1. UI、业务规则、异常和空状态均已实现，而非仅成功路径。
2. 对应需求 ID 的验收标准通过。
3. 关键计算具备单元测试，持久化和跨模块写入具备集成测试。
4. 无硬编码 AI 结果、密钥、沙盒绝对路径或模拟时间。
5. 满足基本 Dynamic Type、VoiceOver、触控区域和对比度要求。
6. 不出现未处理崩溃、数据半写入、重复日志/账目或阻断级问题。
7. 文档中的行为若有变更，同步更新需求和设计，不以代码隐式改变口径。

## 7. 首版后的候选迭代

以下事项不进入首版排期，但当前架构不得阻碍其实现：

- iCloud 私有数据库同步及冲突处理。
- 深色模式完整设计。
- 日志长图/PDF、单株植物档案分享。
- 更多统计周期、自定义报表和花园预算。
- 真实智能设备厂商接入。
- AI 对话流式输出、病虫害辅助观察及更丰富的上下文工具。
